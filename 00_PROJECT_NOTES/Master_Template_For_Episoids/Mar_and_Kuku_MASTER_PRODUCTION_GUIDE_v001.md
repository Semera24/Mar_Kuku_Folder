## 1. Quick start for any AI agent or editor

1. Read the creator's current request and this guide. Identify the episode, intended deliverable, permitted tools, and exact edit scope.
2. Read that episode's current script, audio approvals, actual timing notes, and publishing pack. Historical notes are not current measurements.
3. Identify the active project/timeline and frame rate before any edit. Confirm the working copy or make an app-supported duplicate when needed. Never assume a source named "BackUp" or "Working" is the intended target.
4. Inspect approved source assets and the actual placed audio. Record trims, speed, joins, and exclusive ends. Do not generate substitute characters because a tool cannot find the originals.
5. Make a short scene/cue table, then build one representative shot or chapter. Check the picture and audio before extending the pattern.
6. Keep completed material, source assets, and unrelated tracks unchanged unless the task explicitly includes them.
7. Inspect the finished edit, render the authorised deliverables, verify the actual files, and update that upload's Markdown records.
8. Report what was verified, what was only inferred, and any remaining human review. Never describe sampled frames as complete audiovisual playback.

## 3. Identity and teaching principles

- Public name: **Mar and Kuku**. Tagline: **Learn. Play. Grow.** Legacy internal names such as DoroNesh or Dofe are not the public character names for this series.
- Core audience: approximately ages 3–6, with adults choosing the videos. Use simple international English, clear sung words, and a warm Ethiopian-inspired village world.
- Preserve official character silhouettes, faces, clothing, proportions, and personality across tools. Kuku is a host; a generic chick prop must never replace Kuku.
- Teaching hierarchy: the active learning object first, host reaction second, background life third. Children should be able to point to each object without searching through overlaps.
- Make movement purposeful and visible, with moments of stillness for counting and thinking. More simultaneous motion is not automatically better teaching.
- Keep eggs and flowers in their original approved colours. Chicks have specifically approved colour variations; that approval does not apply automatically to other objects or character skin/clothing.
- Duration follows useful content. Episode 001 is 13:15; a future 30-minute edition needs additional distinct learning/play value. Long compilations are optional, not a channel requirement.

## 6. Coordinate, time, and anchor contract

These rules make the method portable between tools.

```text
Canvas: W × H pixels; project frame rate F.
Reference origin: top-left; x increases rightward, y downward.
Clip range: [startFrame, endFrame), with end exclusive.
Keyframe time: local offset from the clip start, unless explicitly stated otherwise.
Palmier position key: top-left normalised x,y.
Palmier scale key: absolute normalised width,height, NOT a multiplier.
Palmier rotation: clockwise degrees.
Pixel conversion: x_px = x_norm*W; y_px = y_norm*H.
```

Uniform scale must preserve pixel aspect: `width_norm / height_norm = (assetWidth / assetHeight) * (H / W)`. Do not paste widescreen normalised dimensions into a portrait project unchanged.

Active animation keys override corresponding static transform values. Some Episode 001 clips have misleading static centres/widths left from manual work; evaluate the keyed pose before proposing a repair. A static width of 0.60 may coexist with active chick width keys around 0.13. The keyed width is what the viewer sees.

### Grounded breathing and sway — implemented technique

The host appears to rotate about its feet even when the application rotates the PNG around its centre. Scale and position are compensated together.

For a full-image bottom-centre anchor `(footX, footY)` in normalised coordinates, current width `w`, height `h`, and clockwise angle `a` in radians:

```text
centreX = footX + sin(a) * h * H / (2*W)
centreY = footY - cos(a) * h / 2
positionX = centreX - w/2
positionY = centreY - h/2
```

This fixes the rectangle's bottom centre. Real feet may be above the image edge because of transparent padding: calibrate the visible foot point, or use a real pivot/parent there. In a tool with a native foot pivot, use that pivot rather than applying the compensation a second time. Do not vertically bob the whole character while claiming grounded breathing.

Cross-tool transfer must explicitly resolve origin, rotation sign, pixel versus normalised dimensions, clip-local versus composition time, frame 0 versus frame 1, and inclusive render endpoints. In Blender, either use frame 0 or document the +1 offset. In Resolve, subtract any displayed timeline timecode base before comparing relative frames. Test a labelled four-corner still and a two-key motion before transferring a full scene.

## 7. Motion library: proven recipes and reusable starting values

The snapshot preserves measured keys. The simplified recipes below recreate the intent; they do not claim to reproduce every unexposed native interpolation detail.

| Motion | Episode 001 reference | Reuse rule |
|---|---|---|
| Mar breathing/sway | CH05 sample height about 0.630–0.644, rotation about ±2° | Gentle 1–2.3% scale change; foot anchored; vary phase |
| Kuku breathing/sway | CH05 sample height about 0.400–0.409, rotation about ±2.8° | Slightly livelier than Mar; no repeated hopping |
| Flowers | Root-held mild scale motion; rotation approximately ±4° | Keep stems planted and blooms separately countable |
| Eggs | Small scale change and approximately ±2° rocking | Stable basket placement; no rolling out of the group |
| Apples | Later resting width about 0.112; initial settle includes wider overshoot | Preserve seven separate positions; avoid copying an entrance's maximum rotation into the continuous loop |
| Birds | Rest width 0.21; keyed width approximately 0.204–0.218; rotation around ±2.5° | Measure visible silhouette; larger sky layout has explicit approval |
| Chicks | Rest width about 0.13, height 0.217; roughly ±2° sway | Retain the completed ten and their individual spacing |
| Full-episode Detective answer | Question 100%, peak 175%, settled 160% | Clear distractor and place answer centrally; reserve room for overshoot |
| Portrait Detective answer | Question 100%, peak 160%, settled 150% | Smaller peak fits the portrait board; still an obvious reward |

Typical long host cycles are about 5–6 seconds with different phases for Mar/Kuku. The sampled implementation generally sets keys every 15 frames and at the first and last displayed frames. Use the snapshot for actual curves; do not interpret 15-frame key spacing as a 2 fps render. Playback/export remains 30 fps.

### Portable breathing curve

Suggested implementation consistent with the established small motion:

```text
scale(t) = 1 + amplitude*(1-cos(2*pi*t/period))/2
rotation(t) = rotationAmplitude*sin(2*pi*t/swayPeriod + phase)
```

Use approximately 0.01–0.023 scale amplitude and 1–2.8° rotation according to the host/shot. Offset phases rather than moving every layer together. Carry phase across pose changes when practical. Ease loops into and out of a shot so a cut does not introduce a sudden scale jump. Preserve matching anchor position when hard-cutting to a differently padded pose.

### Portrait object pop/settle — implemented

At the cue, the object is already visible at 93% scale; at local frame 6 it reaches 104%; at frame 14 it rests at 100%. Position compensates for the scale so the object does not jump vertically. Existing objects remain visible. Their later sway is restrained, around ±1.8° with a small scale variation. If the next cue arrives sooner, shorten the settle or use a stable highlight rather than colliding animations.

### Pose cuts and holds

Use direct PNG pose changes at invitations, count starts, questions, reveals, reviews, and goodbye. No crossfading two faces or bodies. Use constant/stepped visibility for substitutions; use smooth interpolation for deliberate transforms. Questions need a stable thinking hold. Do not animate the correct answer in a way that reveals it before the answer cue.

## 8. Counting, stages, and review patterns

| Lesson type | Stage and count pattern | Review and clear |
|---|---|---|
| Eggs | Separate table, basket, and three egg layers | Hold three; reset only when a new pass genuinely recounts from one |
| Flowers | Fixed planter and five separately rooted flowers | Mild stem sway, readable blooms; no strong continuous rotation |
| Apples | Upper-right two–three–two cluster, no new tree required | Keep all seven apart; hold the completed group |
| Birds | Nine visible sky positions, including space above hosts if needed | No crossing silhouettes during counts; preserve larger approved size |
| Chicks | Widescreen four–three–three; portrait three–four–three | Retain ten; show approved Number 10 separately |
| Single numbers | One large numeral in a clean teaching area | Clear old numeral before the next unless the game calls for choices |
| Detective | Stable choices, thinking space, then obvious correct answer | Remove/de-emphasise distractors on the answer, not beforehand |
| Goodbye | Readable number recap followed by farewell composition | Finish the learning before the closing card |

Repeated counting passes should have their own purpose: slow teaching, recall, matching, or a game. Reuse object positions for clarity, but vary host reaction and framing where useful. Do not create a new prop for every small word pause. Do not separate a trailing noun from its sung phrase as another object entrance.

For a rapid 4–5–6 passage, one approved approach is a stable row of all three numerals with brief emphasis on the active number. Do not force a long pop into a five-frame interval. That is a reusable design option; Episode 001's final manually shortened number section is not the original long review schedule.

## 9. Audio and cue workflow

Record for every actual placed clip: source filename, timeline start, source trim-in/out, retained duration, exclusive end, speed, gain, fades, and adjacent joins. Read the waveform/transcript as aids. Only listening or a trusted supplied timing authority can establish sung cues; document the confidence.

For an unsplit normal-speed clip at project frame rate `F`:

```text
masterCueFrame = placedStartFrame + round(sourceSeconds*F) - sourceTrimStartFrames
shortCueFrame = round((sourceSeconds - shortSourceStartSeconds)*F)
```

For split or speed-adjusted audio, use the segment's actual source-to-timeline mapping. Never apply the simple formula blindly through a speed curve. Preserve exact frame/sample-derived durations where available instead of accumulating rounded decimal seconds.

Cue statuses: **audibly verified**, **creator-supplied timing**, or **manual review needed**. Keep individual number starts separate. Naming example: `E02_CH03_APPLE_P02_7_START`, `E02_CH04_DETECTIVE_3_QUESTION_START`, `E02_CH04_DETECTIVE_3_REVEAL_START`. Include the pass number to prevent duplicate names. Timeline markers are editing guides, not rendered captions.

Listen for digital silence, duplicated audio, overlapping vocals, clipped words, and abrupt music cuts. Do not layer full mix plus stems unless deliberately mixing them. A music bed repair should have its own named track and explicit range/gain/fade record. No source replacement, stretching, or retiming solely to satisfy stale markers.

## 10. Camera, depth, and natural movement

Implemented in Episode 001: layered 2D PNG transforms and restrained motion. No articulated character rig, Blender 3D camera, full lip-sync, or Fusion composition has been built or verified for this episode.

Recommended future shot grammar:

- Establish the village and hosts; move attention to a teaching close-up; hold during the count; widen for the group review.
- Consider framing every 2–4 seconds, but change it only when the lesson benefits. Do not zoom on every beat or every counted object.
- Start camera push tests around 2–4% over 2–4 seconds. Move a shared scene root/camera so stage, hosts, and objects maintain their relationship. These are proposed starting values, not measured Episode 001 camera settings.
- Add depth with separate foreground, teaching, character, and background layers; a single flattened village PNG cannot provide true independently moving trees and houses.
- Naturalness comes from timing, weight, anticipation, follow-through, clear eye direction, and purposeful pauses. Keep official character shapes and preschool clarity while improving these qualities.

## 11. Practical route across Palmier, Resolve/Fusion, and Blender

Choose one timing/assembly authority for a given episode. A useful future arrangement is **Blender for selected animated shots → Resolve for edit, Fusion composites, sound and delivery**. Palmier can remain the assembly authority when it already does the needed work well. Do not maintain three conflicting editable masters or repeatedly compress finished MP4s between apps.

### Palmier — established workflow

Use MCP to read project/timeline/media, duplicate versions, place approved assets, set transforms/keyframes, and export. Read back after switching timelines because IDs change on duplication. Match the requested visible/session-bound project. Do not modify a live .palmier package with filesystem scripts. Its current canvas settings are project-wide; use a separate portrait project when necessary, as done for the Shorts.

### DaVinci Resolve and Fusion — proposed adaptation, not yet built

Blackmagic documents Fusion's node compositing and spline/keyframe tools. We can use these capabilities to adapt our shot recipes; the following is a proposed setup, not a claim of automatic conversion. [Official Fusion overview](https://www.blackmagicdesign.com/products/davinciresolve/fusion)

```text
Approved PNG -> per-asset Transform (calibrated pivot) -> Merge over Village
                                                     -> shared framing Transform -> output
Approved WAV ----------------------------------------> edit/audio timeline
```

Build separate named branches for stage, objects, hosts, and branding. Use smooth curves for movement and held visibility for pose changes. Save tested reusable compositions/macros with exposed controls for count, cue frames, spacing, scale, and phase. Use Edit for assembly and Fairlight for an actual listening/mix pass; consult the installed version's official training for controls. [Blackmagic training](https://www.blackmagicdesign.com/products/davinciresolve/training)

First test: one 5-second grounded Mar/Kuku shot and one three-object count. Confirm pivots, alpha edges, colour, render size and frame mapping before migrating an episode. Check Free versus Studio feature availability and the installed version; neither edition nor automation access is verified in this guide.

### Blender — proposed adaptation, not yet built

Start with approved PNG cards and a shared scene root; place each host's control/pivot at visible foot contact. Use an orthographic view for a consistent flat presentation, then test intentional depth/parallax separately. Use one named object/collection per counted prop and explicit visibility changes at the cue. Existing single PNG poses are complete images, not automatically rigged limbs.

Blender's Graph Editor/F-curves provide keyframe interpolation and curve control. Bézier curves with Auto Clamped handles are a sensible starting point to limit unintended overshoot; deliberately author any reward overshoot. Match the image-space reference first, then refine movement. [Blender interpolation reference](https://docs.blender.org/manual/en/4.5/editors/graph_editor/fcurves/properties.html)

For looped breathing, use a periodic action/curve or evaluated expression with a phase control; test the first/last frame seam. Parent host art to a foot control instead of manually reproducing centre compensation. Use a distinct object/material variant for approved prop colours. Maintain an unlit/controlled appearance when matching the original PNG colours; test the chosen render engine's alpha and colour management.

Grease Pencil is a separate drawing/animation route suitable for future hand-drawn accents or approved new animation, not an automatic conversion of a PNG into a rig. Its documented workflows include whole-object, drawing, deformation, and inherited animation. [Blender Grease Pencil animation](https://docs.blender.org/manual/sr/4.5/grease_pencil/animation/introduction.html)

For an orthographic calibration, choose a world-space canvas height `Hworld` and width `Wworld = Hworld*W/H`. Map a reference centre with `Xworld=(centreX-0.5)*Wworld`, `Yworld=(0.5-centreY)*Hworld`, and sprite height `h*Hworld`. This is a proposed mapping for a front-facing XY setup; verify camera orientation, rotation sign, ordering and pixel aspect with a test render before using it.

Introduce one improvement at a time in a short test, then reuse it after approval. Do not rebuild Episode 001 to try these methods.

| Priority | Technique | Test and acceptance condition |
|---|---|---|
| 1 | Foot-pivot controllers and reusable loops | Five-second idle: no visible foot slip, no new body distortion |

| 7 | Purposeful bird/leaf motion paths | No crossing or covering objects while they are being counted |

| 10 | Deeper 2.5D scenes and character rigs | Dedicated rigging/design test before episode use; preserve the official 2D identity |

Use anticipation on the host before a reveal, not by showing an uncounted object early. Slow background motion can continue during teaching, while the learning objects settle. Avoid procedural random jitter and constant equal-sized bouncing across every layer.

## 13. Interchange and delivery contract

- Preserve PNG alpha, source aspect ratios, source WAVs, and a frame-based cue manifest.
- For tool-to-tool shots, prefer a verified high-quality intermediate or numbered PNG RGBA sequence plus separate WAV. Use a supported alpha video codec only after checking that both exporter and importer actually preserve alpha; H.264 MP4 is not the transparent asset format for this workflow.
- Name image sequences with fixed-width frame numbers and record start frame, fps, end-exclusive frame and whether the last numbered file is inclusive.
- XML/FCPXML can help transfer timing, but inspect transformed PNGs, crops, keyframes, colour and audio after import. A flattened shot preserves appearance while losing per-object editing.
- Record native render engine, colour management/view transform, alpha interpretation, dimensions, fps and audio rate. Compare against a reference still to catch gamma shifts and dark fringes.
- Default local delivery: 1920 × 1080 or 1080 × 1920 at 30 fps, H.264 MP4, 48 kHz stereo. Higher resolution is a separate source-quality and delivery decision, not an automatic improvement.

## 16. Quality gates

**Before building:** target copy verified; sources found; placed audio measured; cue confidence recorded; frame rate and composition known.

**Before accepting a chapter:** one object per intended cue; prior objects retained; group total correct; no overlapping silhouettes; official host art; anchored feet; gentle rotation; no crossfaded poses; first/last frames and both joins inspected; actual listening review recorded.

**Before accepting a render:** correct timeline and dimensions; complete export status; file exists; technical properties checked; representative exported frames inspected; full decode test where appropriate. Decoder success is a technical integrity check, not proof of word/count synchronisation or rights clearance.

**Before publication:** full listening pass, phone preview, correct title/cover, music/artwork permissions, disclosure decisions, final captions if supplied, accurate made-for-kids setting, upload processing and copyright checks, and creator's publication decision. A clean automated copyright check alone does not establish permission.

The advanced workflow is a proposed development path, not a claim that Blender/Resolve projects or integrations already exist.
